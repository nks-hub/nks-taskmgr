# Seznam úkolů NKS Task Manageru

Vývoj nativní aplikace začal. Tento soubor drží plán, nálezy, review a stav ověření. Původní analýzy, RE podklady a webový návrh jsou mimo repozitář. Dokumentace v repozitáři je omezena na README a TODO. Sestavení a testy probíhají místně; CI se nyní nepřidává.

P0 znamená nutný základ nebo podmínku správnosti, P1 další základní funkci a P2 samostatné rozšíření. Role je budoucí odpovědnost, nikoli již přidělený člověk. Každá položka obsahuje závislost a podmínku dokončení. T01–T48 a T54 tvoří základní rozsah, T49–T53 rozšíření. Celkem je 54 implementačních úkolů.

## Požadavky a přijímací podmínky

- Windows 10/11 x64; správa procesů x64 i WOW64. Win7 ani hlavní aplikace pro x86 OS nejsou požadované.
- Běžný provoz bez práv správce a bez automatického UAC. Každý sběrač používá nejnižší potřebná oprávnění; odmítnutý přístup k senzoru či chráněnému procesu nesmí blokovat ostatní funkce. Případné zvýšení oprávnění je samostatná vědomá akce uživatele.
- Vzhled vychází z Windows 11 Task Manageru s vlastními prvky. Výkon má vlevo jednotlivé prostředky s minigrafy a vpravo detail vybraného zařízení.
- V seznamu jsou vidět všechny disky, GPU a adaptéry včetně odpojených či nepodporovaných; nedostupný údaj není platná nula.
- Kandidáti UI: C++/WinUI, C#/WinUI s Native AOT a C++/Win32/DirectComposition. T06 je porovná nad stejným nativním jádrem a stejným ovládáním.
- Identita procesu obsahuje boot, PID a druh i hodnotu generace. Měnící akce znovu ověřují stejný cíl na stejném handlu.
- CPU používá skutečný monotónní interval a počet logických procesorů napříč skupinami; pracovní sada, soukromá paměť, procesové I/O, fyzický disk a síť jsou odlišené.
- Sběr běží mimo UI; výběr a scroll se při dávkované aktualizaci neztrácejí. Blokující podrobnosti patří do zrušitelného pracovního procesu.
- Běžný vzorek je po 1 s, rychlý pohled po 250 ms. Historie má rozpočet 64 MiB a ukazuje skutečně uchovaný rozsah a mezery.
- Výkonový referenční scénář je Release bez debuggeru, 500 živých procesů a odděleně 10 000 přehrávaných řádků. Hardware a OS se zaznamenávají s měřením mimo Git.
- Cíle: teplý start p95 do 400 ms, studený do 1,2 s, výběr p95 do 50 ms, hledání p95 do 100 ms, rolování p95 do 16,7 ms a stáří dat p95 do 1,25 s.
- Cíle za 60 s po zahřátí: vlastní CPU nejvýše 0,5 % celého PC při zobrazení a 0,1 % při minimalizaci; soukromá paměť do 220 MiB včetně výchozí historie a všech vlastních pracovníků.
- Přijetí vyžaduje funkční klávesnici, čtečku, kontrast, DPI 100/150/200 %, RDP, obnovu po ztrátě GPU a 24 hodin bez trvalého růstu paměti a handlů.
- Správní scénáře se ověřují na vlastních cílech ve VM. Součástí dokončení jsou oprávnění, odmítnutí UAC, export bez testovacích tajemství, podpis a návrat aktualizace.
- Podpora Windows 10, více skupin procesorů a WOW64 se považuje za ověřenou až po příslušném skutečném testu; lokální Windows 11 test ji nenahrazuje.

## Průběžné nálezy a review

- [x] F24 GPU: DXGI při vzdáleném zobrazení vracelo kopii fyzické karty bez software příznaku. Inventář nově ověřuje typ přes D3DKMT a vynechá potvrzený nepřímý adaptér bez renderování; názvy karet neslučuje. Živý test po opravě zachoval dvě fyzické GPU, 24 enginů a platné obě paměti.
- [x] F25 Řazení WinUI: místo původních 645–2505 ms prošlo 56 případů se živými i 10 000 přehrávanými řádky na každém ze tří strojů. Balíček 87fb498 má p95 obsluhy živých řádků na fyzickém Windows 10 18,8 ms a ve Windows 11 VM 14,0 ms; pro 10 000 řádků 9,9/18,5 ms. Dva následující renderovací callbacky u živých řádků činí 88,4/86,0 ms; callback není důkaz fyzické prezentace snímku. Testy ověřují více výběrů, hlavní proces i posun.
- [x] F26 Obnova procesů: viditelné kontejnery a jejich vnitřní prvky zůstávají při obnově zachované; mění se datové vazby. Test ověřil jejich stejné identity po každém řazení a uchování hlavního výběru. Cache zobrazených ikon je omezená na 128 položek.
- [x] F27 Grafy: doplněna měřítka, jednotky, automatický/plný rozsah, kurzor, připnutí a klávesnice; kompaktní hodnota je v záhlaví. Běhové testy prošly všemi prostředky a skutečná klávesnice otevřela připnutou hodnotu. Čtyři procesory tvoří 2×2 se stejnými plochami 332×110 px; samostatné snímání oken ověřilo i deset procesorů ve VM. Přijetí vzhledu zůstává v F13.
- [x] F28 Údaje sestavy: SMBIOS poskytuje rychlost, sloty, typ a provedení RAM; Windows topologii a cache CPU a rychlosti linky v obou směrech. Nativní parser, nové C ABI i zobrazení v UI prošly místně, na Windows 10 a ve Windows 11 VM. Chybějící údaj zůstává označený jako nedostupný.
- [x] F29 Ikona aplikace: obě EXE mají vloženou ikonu; WinUI nastavuje ikonu okna a používá ji také v titulku. Ověřena extrakce nativního EXE i skutečné okno na Windows 10 a hlavní panel Windows 11 VM.
- [x] F30 Další stroje: balíček 87fb498 prošel nativní sadou, celým WinUI testem a 56 případy řazení na fyzickém Windows 10 a virtualizovaném Windows 11. Balíček 9685f53 s diskovými údaji následně na obou strojích prošel všemi 11 nativními testy i WinUI testem bez zvýšení oprávnění. Každý společný balíček má ověřené shodné SHA-256 EXE i DLL. Nejde o celé přijetí T41.
- [ ] F31 Další hardware: Sestava už zobrazuje CPUID, cache, výrobce/model desky a BIOS. Čtecí podpora standardního ovladače UPS je doplněná a stav bez zařízení ověřený; skutečná telemetrie připojené UPS a protokoly jednotlivých výrobců zatím ověřené nejsou. SPD časování zatím není implementované.
- [ ] F32 REA: tabulka importů Správce úloh potvrzuje rozhraní SMBIOS, topologie, PDH a síťových adaptérů; jde o statickou evidenci, ne o důkaz konkrétního běhu. Hlubší dekompilaci zatím blokuje chybějící podporovaný poskytovatel Ghidra/IDA.
- [x] F33 RAM: číslování provedení modulů v SMBIOS se liší od WMI; opraveno rozlišení DIMM, SODIMM a RIMM podle DSP0134. Regrese zahrnuje také CUDIMM.
- [x] F34 Měření: skript chybně odmítal aktivní RDP při zhasnutém fyzickém monitoru. Nově kontroluje GUID_SESSION_DISPLAY_STATUS; stav konzole a číslo relace zapisuje odděleně. Ověřeno proti současnému stavu relace 1 a konzole 0.
- [x] F35 Místní měření CPU/RAM balíčku 223650c: 60 s v popředí a 60 s minimalizovaný. CPU za celé PC činilo 0,198/0,069 %, maximum soukromé paměti 192,7 MiB a pracovní sady 213,4 MiB. Skript ověřuje popředí každých 250 ms a výsledek váže na hash EXE/DLL i verzi EXE. Tento starší scénář splnil místní limity; nové měření ve VM je v F44 a celé přijetí výkonu a 24h běh v T44 zůstávají otevřené.
- [x] F36 Disky: doplněna průměrná odezva, odezvy čtení/zápisu, fronta, IOPS, kapacita, rozhraní, sektory a dostupná teplota i SMART/NVMe zdraví. Zdravotní údaje se čtou po 30 s mimo UI, bez žádosti o zvýšení oprávnění. Na místní sestavě ověřeny teploty tří fyzických disků a nepodporovaný stav virtuálního disku; nativní sada a WinUI test včetně rozbalených údajů prošly. Rozbalení zůstává zachované i při výpadku a návratu údaje SMART.
- [ ] F37 Teploty CPU: prověřit skutečná čidla čipu a jader přes dostupný ovladač; teplotní zóny ACPI nezaměňovat za teplotu CPU. Navržený směr je volitelný zdroj přes čtecí rozhraní senzorové služby, aby UI zůstalo bez správce. Zatím není implementováno ani ověřeno čtení čidel.
- [x] F38 Oprávnění současné aplikace: WinUI používá asInvoker. Balíček 9685f53 prošel místně, na fyzickém Windows 10 i ve Windows 11 VM bez zvýšení oprávnění; nativní diskový test ověřuje přímo TokenElevation a vrací elevated=false. Chybějící podpora senzorů nebrání běžnému provozu. Budoucí teploty CPU zůstávají v F37 a ovladač nesmí být povinný pro spuštění aplikace.
- [x] F39 Tooltip: odstraněna registrace automatické nápovědy Ctrl+F na celé ploše okna; zkratku zpracovává klávesová událost a popisek zůstává pouze u hledání. Ovládaný test ve Windows 11 VM ověřil všechny čtyři pohledy, skutečné Ctrl+F, zachování dotazu při opakování i zobrazení nápovědy pouze nad hledáním. Sestavení Native AOT a review prošly.
- [x] F40 Identita startu systému: procesy nově používají celé 128bitové ID startu Windows místo času. Nativní jádro, C ABI a WinUI zachovávají obě poloviny; staré ABI layouty zůstaly stejné. Balíček b0b1899 prošel místně, na fyzickém Windows 10 i ve Windows 11 VM: 12 nativních testů, Native AOT, WinUI a 56 případů řazení, vše bez správce. Testy zahrnují odmítnutí přístupu, vadné odpovědi, dva nezávislé sběrače a korekci časových údajů. Při nedostupném ID sběr pokračuje s výslovným stavem.
- [ ] F41 Rozložení procesů na pomalejším stroji: při dřívějším střídání tří běhů s ikonami a bez jejich načítání dosáhlo maximum rozložení 361,1/66,7 ms. Rozšířené měření odděluje CPU, GC, části obnovy i přiřazování bitmap. Na Windows 11 VM proběhly další tři běhy po 56 případech bez půlsekundové špičky; samotná přiřazení ikon trvala pod 1 ms. Oddělení Shell dotazů do procesu prošlo třemi dalšími běhy s maximy rozložení 50,5/58,7/56,5 ms, ale příčina původních špiček tím není prokázaně uzavřená. Renderovací callbacky nejsou důkaz fyzické prezentace.
- [x] F42 Ikony: Shell a GDI dotazy běží nejvýše ve dvou pomocných procesech se stejnými právy jako aplikace; po třech sekundách bez odpovědi se příslušný proces ukončí. Soukromé roury přijímají pouze pevné rámce a bitmapu do 1 350 B. Nativní test a WinUI ve Windows 11 VM bez správce ověřily generaci PID, vadné rámce, timeout, nové spuštění i zánik pomocníků po zavření; dalších 168 případů řazení prošlo. Limit se vztahuje na čekání na odpověď, ne na start procesu ani frontu.
- [x] F43 Instalátor a přenosný ZIP: balíček obsahuje Native AOT aplikaci, Windows App SDK, MSVC DLL a licence. Windows 11 VM ověřila instalaci bez správce do profilu uživatele, shodu hashů všech souborů, nabídku Start, skutečný běh, 56 případů řazení, opakovanou instalaci i odinstalaci. Uživatelský soubor zůstal zachovaný a pomocné procesy skončily. Výkonové limity zůstávají v F44; podpis a celé T46 zůstávají otevřené.
- [ ] F44 Výkon instalovaného kandidáta ve Windows 11 VM: 60 s v popředí a 60 s minimalizovaný, včetně dvou stabilních pomocníků pro ikony. CPU za celou VM činilo 1,125/0,239 %, takže cíle 0,5/0,1 % zatím nesplňuje; špička soukromé paměti 122,0 MiB vyhověla. Výsledek obsahuje hashe GUI, nativní knihovny i pomocníka. Měření nově odmítá chybějícího nebo ukončeného pomocníka; žádné ovládané testy neběží na hlavním PC.
- [x] F45 Přehled procesů: panely CPU/RAM se při aktualizaci znovu nevytvářejí, mění se jen jejich texty. Windows 11 VM ověřila zachování prvků, skutečné prokliky na oba prostředky, nativní monitor, WinUI a všech 56 případů řazení. Sběrná vlákna mají názvy pro rozlišení zbývající zátěže; samotnou úsporu musí ještě potvrdit měření v F44.
- [x] F46 Řádky procesů oznamují jen změněné údaje. Test ve Windows 11 VM ověřil nezměněný snímek, první platnou nulu CPU, samostatnou změnu RAM a návrat ze zastaralého či ukončeného stavu; WinUI, řazení a prokliky na prostředky prošly. Všechny surové údaje se dál přijímají; dopad na CPU zbývá změřit v F44.
- [x] F47 Sběr paměti čte přímo systémové statistiky místo drahého GetPerformanceInfo. Ve Windows 11 VM klesl medián celého sběru ze 14,8 na 7,2 ms a CPU sběrného vlákna procesů za 30 s z 594 na 297 ms. RAM, závazek, cache i fondy jádra se shodovaly s původním API; chybové stavy, monitor, ABI, známá alokace RAM, WinUI a 56 případů řazení prošly bez správce. Profil samotného GUI klesl z 0,766 na 0,516 s CPU; nezahrnuje pomocníky ani popředí, takže F44 zůstává otevřené.
- [x] F48 Export T27 ve WinUI má výběr polí, náhled a JSON snímek bez výchozích názvů a identifikátorů. Windows 11 VM bez správce ověřila skutečné uložení přes systémový dialog, shodu náhledu se souborem, samostatné volby názvů/ID a rozložení při 720 × 500. Native AOT test ověřil soukromý testovací údaj, jednotky, stavy, přesnost identity, zachování oprávnění, zamčený cíl, souběžný vznik souboru a chybu úklidu. Integrace s opraveným parserem prošla 43 testy jádra, 128 kontrolami C ABI, WinUI, 56 případy řazení i novým uložením. Review nemá zbývající podstatný nález.
- [x] F49 Obnova nezměněného stromu zachovává odsazení a větve bez zbytečných oznámení. Původní verze vyvolala osm změn, opravená žádnou. Test skutečné tabulky WinUI ověřil aktualizaci při přidrženém pořadí, ukončení i novou generaci PID a zachování vybraného i hlavního živého procesu. Native AOT, 56 případů řazení, navigace a export prošly ve Windows 11 VM bez správce; opakované review nemá zbývající nález. Celé T13 a T15 zůstávají otevřené.
- [x] F50 Parser omezuje čtený název na vlastní záznam za polem vláken. Původní verze přijala sedm vadných případů včetně opakovaného kopírování sdíleného dlouhého názvu; opravená verze prošla 43 testy i živým sběrem ve Windows 11 VM pod SYSTEM i bez správce. Platná dlouhá a prázdná jména i nepoužitá kapacita zůstávají zachované. Přerušení blokujícího systémového volání a celé T08 zůstávají otevřené.
- [x] F51 Teplota GPU zachovává stav odmítnutého přístupu při otevření adaptéru i při dotazu. Osm podvržených scénářů ověřilo stav, zdroj, převod teploty i zavření adaptéru; původní testy výpočtů/historie a živý sběr prošly ve Windows 11 VM pod SYSTEM i bez správce. Jde o ověření zpracování stavů, nikoli teploty skutečné fyzické GPU; nepřidává se UAC ani ovladač.
- [x] F52 Import odmítá i různé generace stejného PID v jediném inventáři, protože export není historie životností. Obě regrese, ostatní kontroly importu a dva skutečné exporty prošly s opraveným Native AOT artefaktem ve Windows 11 VM pod SYSTEM i bez správce. Opakované review nemá další nález.
- [x] F53 Poškozený JSON včetně neplatných Unicode znaků skončí chybovou zprávou v okně porovnání. Načítání převádí chyby dekódování na InvalidDataException a UI ji zachytí. Native AOT ověřil devět vadných Unicode případů i platné znaky; skutečná importní cesta WinUI ověřila chybu a úspěšný opakovaný import 10 000 procesů ve Windows 11 VM bez správce. Původní testy zůstaly zachované a opakované review nemá další nález.
- [x] F01 Sestavení: MSBuild x64 načítal jiný kořen UCRT než SDK; místní build skript ověřuje skutečný SDK a nastavuje UCRTContentRoot jen pro podřízené procesy.
- [x] F20 Služby: změna výběru nyní zruší čekající detail i jeho chybu a odmítne dokončení předchozího dotazu podle verze výběru. Test rychlého přepnutí ověřil správný nový detail a nezávislou životnost starého snímku.
- [x] F21 WinUI: vodorovný posuvník služeb dával tabulce neomezenou šířku; dlouhé názvy potom zbytečně odsouvaly stav a další sloupce. Šířka tabulky nyní vychází z viditelné plochy a pevného minima pro posuvník.
- [x] F22 Výkon: procesy podle CPU se chybně ukazovaly také u disků, sítě a GPU. Obě UI je nyní zobrazují jen u CPU; paměť zachovává pořadí podle pracovní sady. Běhový test prošel všemi deseti prostředky.
- [x] F23 Paměť WinUI: revize ba8dfa5 v GPU detailu překročila místní limit 220 MiB špičkou 259,6 MiB. Graf nyní používá jednu lomenou čáru místo objektu pro každý bod, panel údajů se znovu používá a stejný vzorek neobnovuje geometrii při každém procesovém snímku. Běhové testy souřadnic, mezer, výplně a opakované obnovy prošly. Opakované měření 8e95e66 snížilo maximum GPU scénáře na 164,7 MiB; tento místní scénář už limit splnil. Celé T44 zůstává otevřené.
- [ ] F02 Výkon: měření nyní odděluje nativní dotaz, parser, systémové čítače a výpočty; lokální špičky převládají v systémových dotazech. Omezit jejich dopad a ověřit přijímací scénáře; burst test není důkaz klidové spotřeby ani výkonu UI.
